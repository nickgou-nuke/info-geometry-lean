# `docs-map` Manifest Schema

This document specifies the **crosswalk manifest** that maps the thesis narrative
(blueprint chapters/sections/nodes) to the compiled Lean declarations discovered by
`scripts/ExportDecls.lean`.

The manifest is the stable interface between:

- Lean code (`InfoGeometry/...`)
- Blueprint/LaTeX narrative (`blueprint/src/...`)
- Generated coverage + cross-reference outputs (`docs-map/*.json`, `docs/auto/*.md`)

The central design principle is:

- **Narrative IDs are stable**
- **Lean declaration names may change**
- The manifest absorbs refactors so the thesis does not break

---

## 1. Files in the `docs-map` pipeline

### Inputs

- `docs-map/manifest.json` (hand-maintained)
- `docs-map/declarations.json` (generated by `scripts/ExportDecls.lean`)

### Derived outputs

- `docs-map/resolved.json` (manifest with Lean names resolved)
- `docs-map/coverage.json` (coverage and unresolved-node report)
- `blueprint/src/generated/content.auto.tex` (generated blueprint nodes/stubs)
- `docs/auto/index.md` (generated chapter↔module↔declaration index)

---

## 2. Top-level schema (`manifest.json`)

```json
{
  "project": { ... },
  "paths": { ... },
  "renderDefaults": { ... },
  "chapters": [ ... ]
}
```

### 2.1 `project` (required)

Identifies the Lean project and default namespace for extraction.

```json
{
  "name": "InfoGeometry",
  "importModule": "InfoGeometry",
  "namespace": "InfoGeometry"
}
```

Fields:

* `name` (string, required)

  * Human-readable project name.
* `importModule` (string, required)

  * Root Lean module imported by the declaration extractor.
* `namespace` (string, required)

  * Namespace prefix used to filter declarations.

---

### 2.2 `paths` (required)

Canonical file locations used by the scripts.

```json
{
  "declarationsJson": "docs-map/declarations.json",
  "resolvedJson": "docs-map/resolved.json",
  "coverageJson": "docs-map/coverage.json",
  "blueprintTex": "blueprint/src/generated/content.auto.tex",
  "markdownIndex": "docs/auto/index.md"
}
```

Fields:

* `declarationsJson` (string, required)
* `resolvedJson` (string, required)
* `coverageJson` (string, required)
* `blueprintTex` (string, required)
* `markdownIndex` (string, required)

All paths are repository-relative.

---

### 2.3 `renderDefaults` (optional)

Controls generated output behavior.

```json
{
  "autoNodeEnvironment": "theorem",
  "emitAutoNodes": true,
  "emitChapterHeaders": true
}
```

Fields:

* `autoNodeEnvironment` (string, optional)

  * Default TeX environment for generated stubs (informational only; current generator
    infers environment from declaration kind when possible).
* `emitAutoNodes` (boolean, optional, default `true`)

  * Emit the “Auto-generated coverage nodes” subsection in generated TeX.
* `emitChapterHeaders` (boolean, optional, default `true`)

  * Emit chapter headers in generated TeX.

---

## 3. Chapter schema

`chapters` is a list of chapter descriptors, typically aligned with thesis chapters.

```json
{
  "id": "ch3",
  "number": 3,
  "title": "Projective Geometry of Information",
  "modulePrefixes": [
    "InfoGeometry.Ch03_Projective",
    "InfoGeometry.Projective"
  ],
  "includeUnmappedDecls": true,
  "sections": [ ... ]
}
```

Fields:

* `id` (string, required)

  * Stable chapter ID used in generated reports.
  * Recommended format: `ch3`, `ch4`, `ch5`.
* `number` (integer, optional)

  * Human chapter number for display.
* `title` (string, required)

  * Chapter title.
* `modulePrefixes` (array of strings, required)

  * Module/namespace prefixes used to auto-assign unmapped declarations to this chapter.
  * Matching is prefix-based against both declaration `module` and declaration `name`.
* `includeUnmappedDecls` (boolean, optional, default `false`)

  * If `true`, the generator creates auto coverage nodes for declarations in this chapter’s
    module prefixes that are not explicitly mapped.
* `sections` (array, required)

  * Ordered list of thesis sections.

### Prefix matching semantics

A declaration matches a prefix `P` if either:

* `module == P` or `module.startswith(P + ".")`, or
* `name == P` or `name.startswith(P + ".")`

This allows you to move declarations across modules within the same namespace family
without losing chapter auto-coverage.

---

## 4. Section schema

Sections group narrative nodes in thesis order.

```json
{
  "id": "ch3-2",
  "title": "Projective reduction and gauge invariance",
  "nodes": [ ... ]
}
```

Fields:

* `id` (string, required)

  * Stable section ID.
* `title` (string, required)

  * Section title used in generated TeX/Markdown.
* `nodes` (array, required)

  * Ordered list of narrative nodes.

---

## 5. Node schema (core mapping unit)

A **node** is a narrative statement/definition in the thesis blueprint.
It can map to one Lean declaration, many Lean declarations, or a refactor-safe list of alternatives.

### 5.1 Minimal node

```json
{
  "label": "thm:ch3-logsum",
  "kind": "theorem",
  "title": "Log-sum inequality",
  "render": "stub",
  "leanAnyOf": [
    "InfoGeometry.Discrete.LogSumIneq.logSumIneq",
    "InfoGeometry.Ch03_Projective.LogSumIneq.logSumIneq"
  ]
}
```

### 5.2 Full node with milestone extraction

```json
{
  "label": "thm:ch4-posterior-min-free-energy",
  "kind": "theorem",
  "title": "Posterior minimizes variational free energy",
  "render": "leannode",
  "milestone": true,
  "leanAnyOf": [
    "InfoGeometry.Estimation.Variational.posterior_minimizes_free_energy",
    "InfoGeometry.Ch04_Thermodynamics.Variational.posterior_minimizes_free_energy"
  ],
  "uses": [
    "thm:ch4-kl-bregman"
  ]
}
```

### 5.3 Many-to-one narrative node

Use `lean` (list) when one thesis node corresponds to multiple Lean declarations
(e.g. helper lemmas + main theorem, or split theorems).

```json
{
  "label": "thm:ch4-variational-bayes",
  "kind": "theorem",
  "title": "Variational Bayes free-energy principle",
  "render": "stub",
  "lean": [
    "InfoGeometry.Estimation.Variational.free_energy_def",
    "InfoGeometry.Estimation.Variational.posterior_minimizes_free_energy",
    "InfoGeometry.Estimation.Variational.posterior_unique_under_convexity"
  ]
}
```
