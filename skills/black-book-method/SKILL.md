# Black Book Method

Use this skill when the user invokes the Black Books, knowledge alchemy, analytic psychology, symbolic generation, theorem distillation, or the movement from imaginal/theoretical material into Lean.

This is not a generic coding workflow. It is a disciplined transformation pipeline:

```text
symbolic pressure -> invariant extraction -> repo corridor -> bridge transport -> canonical reduction -> Lean verification
```

## Core Boundary

- Symbolic and alchemical language is legitimate upstream research material.

- Black Book chapters are generative constitution and corridor-finding instruments, not final mathematical authority.

## Method

### 1. Receive Symbolic Material Without Premature Compression

Do not dismiss dense metaphor, multilingual commentary, or imaginal terms as bloat.

Extract candidate invariants:
- named operators
- representation changes
- decomposition patterns
- symmetry/involution claims
- commutator/defect/residual claims
- closure or vanishing claims
- bridge vocabulary between prose, LaTeX, Python/SymPy, graph topology, and Lean

### 2. Distill Without Counterfeiting

Separate:
- live symbolic content
- mathematical claim
- repo-native owner surface
- missing theorem obligation
- rhetoric that must remain only commentary

Do not turn a metaphor into a theorem name unless there is an explicit formal object and bridge path.

### 3. Map To The Repository Corridor

Find where the content belongs:
- owner file: primitive object or root theorem surface
- translator file: adjacent representation transport
- coherence file: agreement of bridges
- capstone file: synthesis only after lower corridors exist
- debt document: if substrate is not ready

Use Arango/gravity retrieval to locate nearby theorem mass, but only as navigation. Read raw Lean before editing.

Useful command pattern:

```bash
python3 tools/infra/arango_gravity_context.py --query "<concepts>" --top-k 12 --json-out /tmp/gravity.json --md-out /tmp/gravity.md
```

### 4. Preserve Bridge Commentary

Comments and docstrings may be part of the theorem-transport substrate.

Preserve or expand comments that map between:
- natural language
- Black Book symbolism
- LaTeX
- Python/SymPy
- Lean declarations
- Arango/InfoTree topology

Do not shorten bridge-bearing comments for style.
Flag comments only if they make unsupported closure claims, misidentify formal objects, or hide missing derivations.

### 5. Reduce Canonically

Prefer the smallest truthful formal move:
- canonical constructor
- decomposition lemma
- explicit residual/defect definition
- zero-deviation special case
- source-backed bridge theorem

Do not invent grand theorem surfaces before owner lemmas exist.
Do not add `sorry`.
Do not hide missing proof obligations inside structure fields.

### 6. Verify And Leave Debt Explicit

Run targeted Lean/lake checks for touched modules and immediate downstream users.

If closure is incomplete, say exactly what remains:
- missing owner lemma
- missing inequality
- missing local-context serialization
- missing expression graph
- missing witness theorem
- stale Black Book-to-code mapping

## Losslessness Rule

For InfoTree/Arango/topology work:
- raw truth is preserved first
- overlays are additive
- SCC/module/hydration labels are coarse-graining layers
- witness/projection edges must descend back to raw source
- unknown compiler state is `null`/absent plus leakage, never fake zero
- normal validation can pass while strict lossless correctly fails

Never call a projection lossless unless the validator proves the relevant lossless contract.

## Output Pattern

When applying this method, report:

- `BLACK_BOOK_SOURCE:` chapter/concept used, or `none`
- `SYMBOLIC_CLAIM:` concise statement of the symbolic material
- `DISTILLED_INVARIANT:` formal candidate extracted from it
- `REPO_CORRIDOR:` owner/translator/coherence/capstone files
- `GRAPH_CONTEXT:` Arango/InfoTree evidence used, if any
- `FORMAL_MOVE:` exact code/doc/tooling change, or why none was made
- `LEAN_GATE:` commands and results
- `REMAINING_DEBT:` explicit obligations, not rhetoric

## Hard Rejections

Reject:
- proof by metaphor
- graph proximity as theorem evidence
- `.olean` or DAG data presented as full InfoTree losslessness
- comment deletion based on density heuristics
- symbolic inflation that gives physical names to trivial algebra
- fake closure through assumptions, `sorry`, or unverified witness packages

## UTMOST MANDATE: Native Lean proof closure over witness/certificate scaffolding

Effective immediately, replacing witness-gated and external-certificate leftovers with native Lean proofs is the top-priority mandate.

Policy requirements:
- Witness packets, certificate fields, external certificates, and assumption interfaces are temporary scaffolding only.
- They are not final mathematical closure and not promotion authority.

- When a native Lean proof is not yet available, the gap must be recorded explicitly as open closure debt; do not package it as complete.
- **Do not “resolve” debt with wording.** Progress must be structural, not just textual.
- **Do not remove debt labels** unless there is a native explicit Lean proof term checked by the kernel closing that specific debt.
- **Real progress** = replacing certificate/witness fields with theorem-backed native derivations.
