# Generative Discovery Architecture

> Status: `current authority`
> Audited: 2026-05-02
> Note: Maintained description of the repository's generative-cognitive discovery layer.
> See: [README.md](../README.md), [docs/README.md](README.md), [docs/CODEBASE_STATUS.md](CODEBASE_STATUS.md)

This repository is not only a theorem library and audit toolchain.

It also implements a generative discovery architecture in which new theorem
pressure is produced through structured LLM dialogue, symbolic reformulation,
Socratic contradiction, packetization, and only then formal closure.

## Core Claim

The repo is designed as a coupled system with two regimes:

1. generative cognition
   - idea emergence
   - symbolic excitation
   - Socratic reformulation
   - contradiction and differentiation
2. logos / authority
   - typed packetization
   - owner mapping
   - Lean proof attempts
   - build and audit gates

In short:

```text
generation may propose;
Pauli may differentiate;
Lean and build gates alone may integrate.
```

## Why This Matters

The repository’s novelty is not just that it verifies mathematics.
It also treats discovery as an engineered workflow.

The LLM is not used only as an autocomplete tool.
It is used as a structured excitation engine that searches for weak,
low-probability, high-structure motifs and then subjects them to Pauli-style
admissibility pressure before formalization.

## The Pauli Auditor

The Pauli auditor is a live part of the architecture, not a historical flourish.

Its function is to ask, before formal integration:

```text
is this even true?
```

That question is the repository’s anti-inflation force.
It rejects:

- decorative closure
- wrappers pretending to be mathematics
- symbolic intensity without owner grounding
- beautiful but underived bridges

## The Generative Loop

The implemented loop is:

1. symbolic pressure enters from a source
   - Black Book material
   - ArXiv or external notes
   - current theorem tension
   - stalled proof corridor
2. Jungian pass
   - broadens the representational field
   - generates alternate motifs and theorem images
   - does not claim truth
3. Socratic regeneration
   - rephrases, challenges, compresses, and repairs candidate ideas
   - searches for a coherent symbolic chain that survives contradiction
4. translator normalization
   - converts symbolic claims into owner-path candidates and statement shapes
5. Pauli pass
   - rejects decorative, inflated, or underived material
   - keeps only corridor-ready candidates
6. packetization
   - records epistemic status and lineage
7. Lean / build / audit
   - formal closure begins only here

## Current Operator Interpretation

If you are a new user, read this layer as:

- the repo is a discovery machine, not just an automator
- novelty is allowed at the generative stage
- Pauli severity is a required stage, not a stylistic preference
- truth is still forced through strict closure gates

If you are editing code, read this layer as:

- symbolic richness is allowed before proof
- theorem authority begins only when the candidate reaches current owner files
  and survives Lean/build checks

## Current Boundary

This architecture does not authorize free-form invention inside theorem files.

It authorizes a disciplined upstream lane for producing better theorem
candidates than a purely reactive workflow would produce.
