# Evidence Schemas for Track B + DIII/Andreev Corridor

This ledger indexes the external artifact formats used by the DIII/Andreev corridor.
All evidence is **out-of-kernel**.
Lean theorems remain in `Projective` and `OperatorAlgebra` bridge modules.

## 1) `andreev_diii_kasparov_witness.v1`

Generated by:

```bash
python3 formalizations/andreev_diii_kasparov_witness.py --json [--out PATH]
```

Schema shape:

```json
{
  "schema": "andreev_diii_kasparov_witness.v1",
  "is_verified": true | false,
  "status": "verified" | "failed",
  "message": "..."
}
```

Interpretation:
- `is_verified = true` is required for corridor ingestion as a finite-sign check pass.
- `status = failed` means a runtime algebraic check failed (e.g. matrix identity mismatch).

## 2) `non_iso_conf3_rank32_external_audit.v1`

Generated by:

```bash
python3 proofs/non_iso_conf3_rank32_external_audit.py \
  --script compute_derham.m2 \
  --m2-timeout 900 \
  --output artifacts/non_iso_conf3_rank32_external_audit.json
```

Schema shape:

```json
{
  "schema": "non_iso_conf3_rank32_external_audit.v1",
  "generatedAt": "...",
  "dim_ambient": 8,
  "betti_numbers": [1, 2, 1, 0],
  "total_rank": 4,
  "is_verified": true,
  "status": "verified",
  "engine": "Macaulay2/BernsteinSato",
  "source": "compute_derham.m2",
  "message": "optional"
}
```

Possible `status` values:
- `verified`: parsed certificate and verified list/rank are present;
- `timeout`: wall-time exceeded;
- `execution-failed`: backend failed;
- `parse-failed`: result marker present but not decodable;
- `missing-backend`: `M2` binary missing.

Interpretation:
- Only `status = verified` and `is_verified = true` are accepted as a positive Track-B certificate.
- All other statuses are non-proof metadata and should be treated as assumptions/known-failures.

## 3) `compute_derham_track_b.py` status stream

This helper is a convenience for local launching/monitoring of `compute_derham.m2`.
A sample invocation:

```bash
python3 formalizations/compute_derham_track_b.py \
  --launch --watch --script compute_derham.m2 --log /tmp/compute_derham.out
```

This script prints a compact JSON object with process/watch markers, not a final theorem status.
Canonical fields include:
- `started`
- `warning`
- `localization_completed`
- `ext_started`
- `result_marker`
- `result_excerpt`
- `status` (`completed`/`running`/`timed_out`/`idle`/`unknown`)
- `pid` and `process_state`

It is intended as operational evidence for running heavy backends, not as a theorem certificate.

## 4) Command provenance schema (strongly recommended)

Track-B heavy invocations should include at minimum:

```json
{
  "schema": "run_provenance.v1",
  "command": "python3 proofs/non_iso_conf3_rank32_external_audit.py --script compute_derham.m2 --m2-timeout 900 --output artifacts/non_iso_conf3_rank32_external_audit.json",
  "start_utc": "...",
  "end_utc": "...",
  "proc_id": "pid:integer-or-null",
  "exit_code": 0,
  "status": "completed|timed_out|failed",
  "stdout_excerpt": "...",
  "stderr_excerpt": "...",
  "artifact_paths": [
    "artifacts/non_iso_conf3_rank32_external_audit.json",
    "artifacts/non_iso_conf3_rank32_external_audit.log"
  ],
  "artifacts_verified": false
}
```

Interpretation:
- For any external run used in freeze/release notes, include `run_provenance.v1` with this minimum to make non-proof/fail modes auditable.

## 5) Suggested index manifest convention

Keep the schema payload and provenance together. For Track B, prefer:

```bash
# schema payload
artifacts/non_iso_conf3_rank32_external_audit.json

# matching invocation-level record
artifacts/non_iso_conf3_rank32_external_audit.json.meta.json
```

A minimal index companion:

```json
{
  "schema": "kasparov_krein_diii_evidence_index.v1",
  "manifest": "docs/KASPAROV_KREIN_DIII_MANIFEST.json",
  "artifacts": [
    "artifacts/non_iso_conf3_rank32_external_audit.json",
    "artifacts/non_iso_conf3_rank32_external_audit.log",
    "artifacts/derham_track_b_status.json"
  ]
}
```
