# Multi-Level Ontology, Taxonomy, and Phylogenesis Skill

Use this skill when unifying ontological, taxonomic, phylogenetic, and epistemic-compiler lanes across `info-geometry-lean`, or when aligning repository knowledge-graph infrastructure with formal ontology literature.

## 1. Theoretical Foundations from the Literature

1. **Taxonomy (Static Subsumption / `is-a`)**:
   - Classifies entities into nested hierarchy trees by necessary and sufficient structural properties.
   - **In `info-geometry-lean`**: Owned by `InfoGeometry.OperatorAlgebra.OntologyRing.projectorSubspace P hP = {x : B | P * x = x}` and `InfoGeometry.OperatorAlgebra.PeirceSpine.cladeSubsumes Psub Panc` (`Psub * Panc = Psub ∧ Panc * Psub = Psub`).
   - **Key Bridge Theorem**: `cladeSubsumes_projectorSubspace_subset` proves that algebraic two-sided idempotent absorption implies set-theoretic subspace inclusion `projectorSubspace Psub hSub ⊆ projectorSubspace Panc hAnc`, while `cladeComplement Psub Panc = Panc - Psub` splits the ancestor class into disjoint orthogonal daughter classes (`cladeComplement_projectorSubspace_disjoint`).

2. **Phylogenesis / Cladistics (Genealogical Lineage)**:
   - Reconstructs historical/derivational branching trees (*cladograms*), Most Recent Common Ancestors (MRCA), shared derived characters (*synapomorphies*), and character-state transformations (Hennig; Wiley & Lieberman; Wheeler).
   - **In `info-geometry-lean`**:
     - **Operator Algebra (`CladisticPhylogenesisBridge.lean` & `OntologyRing.lean`)**: Orthogonal sister clades `Pl, Pr` share the algebraic MRCA `cladeJoin Pl Pr = Pl + Pr` (`cladeFork_mrca`), while the tripotent bifurcation operator `cladeFork Pl Pr = Pl - Pr` assigns synapomorphic polarity `+1` to `projectorSubspace Pl hL` and `-1` to `projectorSubspace Pr hR` (`cladeFork_character_polarity_and_mrca_inclusion`). Iterative evolutionary mutations along a lineage are generated by `phyloLineage n P A = daughterIdemTower n P A`.
   - **Repository history graph (`InfoGeometry.Graph.DarwinCommitTaxonomy`)**: Git commits are `CommitNode`s joined by typed `CommitEdge`s (`parent_of`, `touches`). The parent relation records version ancestry and is not a Lean theorem-dependency relation.
   - **Declaration dependency graph (`JungianEpistemicCompiler`)**: `usesPremise` records a declaration's premise dependency; `blastRadiusEdge` is its converse, describing impact direction. These are two orientations of one relation, not a phylogenetic tree. Acyclicity must come from the actual declaration graph or an explicit hypothesis; the abstract relation alone does not prove it.
   - Keep commit ancestry, declaration dependencies, taxonomic subsumption, and formal bridge theorems as separately typed relations. Connect them only through explicit source/version mappings or proved maps. A shared module path or commit touching a file does not establish that its declarations are mathematically equivalent or dependent.

3. **Multi-Level Ontology Architecture (MLT / OCA / Clabjects / Powertypes)**:
   - **Atkinson & Kühne (Orthogonal Classification Architecture & Clabjects)** and **Carvalho, Almeida, Fonseca, Guizzardi (MLT / UFO-MLT)**:
     - Distinguishes *linguistic metamodeling* (Lean 4 syntax: `Expr`, `ConstantInfo`, `lean_module`) from *ontological instantiation* across multiple domain strata (`M₀ → M₁ → M₂ → M₃`).
     - An entity at an intermediate stratum is a **clabject** (simultaneously an *instance* of a higher-level metaclass/powertype and a *class/type* whose extension consists of lower-level instances).
     - Strictly separates `instantiates` (cross-level, irreflexive, anti-transitive without wormholes) from `specializes / cladeSubsumes` (intra-level, reflexive, transitive partial order).
   - **In `info-geometry-lean`**:
     - `InfoGeometry.OperatorAlgebra.OntologyRing.OntologyMetaLevel` formalizes the 4-stratum chain `M0_StateIndividual → M1_ProjectorClabject → M2_GrassmannianPowertypeOrbit → M3_ErlangenCasimirMetaLaw` with `instantiatesEdge_rank_succ` (no level-skipping wormholes) and `instantiatesEdge_acyclic`.
     - `InfoGeometry.Meta.Architecture.RepDepth` (`L0_Count` through `L5_ThermodynamicClosure`) enforces non-regressive, wormhole-free cross-level dependencies across the repository DAG.

## 2. Strict No-Wrapper Formalization Rules

- Model the overall repository knowledge as a typed multigraph. Topologically
  order only the actual acyclic declaration-dependency projection. Equivalence,
  representation, analogy, subsumption, commit ancestry, and evidence links
  have their own semantics and may have cycles or different carriers; do not
  force them into one global DAG.

- **Never introduce wrapper structures** (`Datum`, `Evidence`, `Certificate`, `CasimirCenter`, `OperatorGrassmannian`, etc.) that bundle operators with hypotheses.
- Express all ontological, taxonomic, and phylogenetic laws as **explicit, owned theorems with explicit hypotheses** over `[Ring B]` / `[StarRing B]` in native Mathlib Lean 4.
