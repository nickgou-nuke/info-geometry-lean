> Created: 2026-05-07

> Authority: design doctrine only; Lean, Lake, audit, and promotion gates remain authoritative for theorem claims.

## 0. Thesis

The Hive should be understood as a symbolic-cognitive theorem factory, not as a
mere multi-agent queue and not as an ordinary GraphRAG application.

Its distinctive architecture is:

```text
common-unconscious symbolic memory
  -> cognitive-function transformation lanes
  -> Socratic and Pauli adversarial conscience
  -> typed Hive packet lineage
  -> Lean / Lake / Audit / Promotion authority gates
```

The common unconscious is a generative and navigational substrate. It may bias
retrieval, generate questions, suggest analogies, surface forgotten motifs, and
produce theorem-candidate pressure. It must not prove, verify, build, audit,
promote, or rewrite theorem authority.

Canonical law:

```text
generation may propose;
Socrates may interrogate;
Pauli may differentiate and quarantine;
Lean and Lake may verify;
Audit may judge semantic hygiene;
Promotion may admit, hold, or quarantine.
```

## 1. Why this architecture exists

The repository has already moved toward a layered discovery architecture:

- Lean owns theorem truth.
- Lake/build owns compilation truth.
- Pauli-style audit owns anti-inflation pressure.
- generated reports and symbolic notes are snapshots or prima materia.
- packetization records lineage before formal closure.
- Arango/DAG layers support navigation, retrieval, and provenance.
- Hermes Swarm / Kanban can provide the cockpit and persistent agent embodiment.

The new design makes this implicit movement explicit. It gives the Hive a
neural backbone: a typed memory and transformation system whose generative
layers are powerful but mechanically prevented from becoming hidden authority
channels.

## 2. Position relative to the field

### 2.1 Standard RAG and GraphRAG

Most RAG systems do:

```text
documents -> chunks -> embeddings -> retrieved context -> synthesized answer
```

Most GraphRAG systems add:

```text
entities -> graph edges -> communities -> graph-conditioned retrieval
```

They are useful for recall, but they often blur epistemic categories:

```text
source text
model inference
graph proximity
semantic analogy
truth claim
```

The Hive should do the opposite. It should label every transformation and every
claim by authority level, cognitive origin, symbolic layer, and admissible use.

The Hive is therefore not just GraphRAG. It is typed epistemic GraphRAG with a
formal proof authority boundary.

### 2.2 Agent orchestration systems

LangGraph, AutoGen, CrewAI, Semantic Kernel, and related systems are useful for
agent routing and tool execution. Hermes Workspace Swarm adds a particularly
useful local cockpit: persistent workers, tmux lanes, role cards, Kanban,
Reports/Inbox, checkpoint routing, and review gates.

The Hive should use this kind of swarm system as embodiment and operator
surface, but not as mathematical authority.

```text
Hermes Swarm = cockpit and persistent worker embodiment
Hive = domain packet ledger and cognitive memory
Arango = layered graph substrate
Lean = theorem truth authority
Lake = compilation authority
Pauli/Audit = semantic anti-inflation authority
Promotion = admission authority
```

### 2.3 Cognitive architectures

Classical cognitive architectures such as SOAR, ACT-R, LIDA, Global Workspace,
OpenCog, and modern neuro-symbolic systems usually model cognition in terms of
working memory, procedural memory, episodic memory, attention, global broadcast,
and action selection.

The Hive can borrow this architecture while specializing it for theorem
discovery:

```text
working memory       = Kanban / active Hive packets / Swarm missions
episodic memory      = packet lineage / fossils / deadends / replay traces
semantic memory      = Alexandria / semantic Arango / source and concept graph
procedural memory    = skills / scripts / worker profiles / wrappers
attention            = MotherBee priority and routing
global workspace     = Hermes Swarm cockpit + Reports/Inbox
verification faculty = Lean / Lake wrappers
conscience           = Socrates + Pauli audit
imagination          = Jungian / Black Book / prima materia generation lane
```

The Hive is therefore best viewed as a proof-oriented cognitive architecture.

## 3. Psychological and neurobiological borrowings

This document uses analytic psychology and cognitive neurobiology as design
metaphors and operational priors, not as theorem authority.

### 3.1 Jungian analytic psychology

The design borrows four key ideas from Jungian analytic psychology.

#### Common unconscious

The common unconscious is the reservoir of symbolic forms, historical methods,
old documents, Black Book material, archetypal patterns, mathematical myths,
failed attempts, and latent connections distributed through human knowledge and
LLM pretraining.

In the Hive this becomes a labelled GraphRAG layer:

```text
common_unconscious nodes:
  archetypal motifs
  alchemical stages
  Black Book symbols
  historical method motifs
  old-doc residues
  theorem-pressure images
  failed proof fossils
  recurring analogies
```

Allowed uses:

```text
retrieval_bias
question_generation
candidate_generation
motif_detection
source_resurfacing
```

Forbidden uses:

```text
proof
build verification
audit bypass
promotion
theorem-status rewrite
```

#### Four functions of consciousness

The four Jungian functions become Hive cognitive lanes:

```text
sensing   -> source intake and exact observation
intuition -> motif formation and candidate emergence
thinking  -> formal decomposition and proof-facing structure
feeling   -> value, salience, significance, and human priority
```

Each packet may carry:

```json
{
  "cognitive_function": "sensing | intuition | thinking | feeling",
  "cognitive_role": "primary | auxiliary | adversarial | integration"
}
```

#### Individuation as integration

A theorem candidate begins as undifferentiated prima materia. It becomes
individuated only when symbolic pressure, critique, formal owner mapping, proof
verification, and audit have been integrated without collapse.

The Hive should preserve every failed stage rather than erase it. Deadends,
fossils, Pauli blocks, and missing hypotheses are part of the system's memory.

#### Shadow discipline

The repository already distinguishes owner, translator, coherence, capstone, and
shadow lanes. The symbolic shadow may reveal missing structure, but shadow
packets must not discharge owner obligations without explicit bridge packets and
Lean-backed verification.

### 3.2 Pauli severity

Pauli is the anti-inflation faculty.

Pauli asks:

```text
Is this even true?
What hypothesis is hidden?
What owner theorem is missing?
Is this merely a scalar shadow?
Is metaphor pretending to be mathematics?
Is a graph edge being treated as proof?
Is a generated bridge decorative rather than derived?
```

Pauli packets should not be treated as theorem authority either. They are
semantic quarantine and critique authority. Their role is to block or constrain
ascent.

### 3.3 Socratic interrogation

Socrates is the destabilizing question engine.

Socratic packet types should record questions such as:

```text
What is the weakest precise version?
What would falsify this?
Which term is undefined?
Which direction is proved?
Which hypotheses are missing?
Which Lean owner file should own this?
What prior deadend resembles this candidate?
```

Socrates does not verify. Socrates turns symbolic pressure into better questions
and safer candidate shapes.

### 3.4 Alchemical process states

Alchemy is useful as a process-state language:

```text
nigredo    = raw confusion, contradiction, prima materia
albedo     = purification, separation, hypothesis extraction
citrinitas = emergence of theorem image / invariant candidate
rubedo     = integration after proof, audit, and promotion
```

These labels should be carried as symbolic process metadata, not as authority
claims.

```json
{
  "symbolic_stage": "nigredo | albedo | citrinitas | rubedo"
}
```

Important: `rubedo` is only permitted for packets that have passed the required
Lean/Lake/Audit/Promotion chain, or as a purely symbolic label with
`promotion_allowed = false`.

### 3.5 Cognitive neurobiology analogues

The Hive can also borrow disciplined structure from cognitive neurobiology.
These are architectural analogies, not biological claims.

#### Global workspace

Hermes Swarm + Reports/Inbox + Kanban form the global workspace: the currently
broadcast state visible to operators and named agents.

#### Hippocampal indexing and replay

Packet lineage, fossils, deadends, and replay traces act like episodic memory.
They allow the system to re-enter old attempts under new context instead of
forgetting failure.

#### Thalamic routing

MotherBee routes signals between sensory intake, symbolic memory, proof lanes,
audit lanes, and promotion gates. It should not perform every function itself.
It should route and regulate.

#### Basal-ganglia-like gating

Authority transitions are gated actions. A packet should not climb from
`proposal` to `lean_checked`, `build_checked`, `audit_checked`, or `promoted`
without the corresponding wrapper or authority gate.

#### Predictive processing

The Hive continuously generates candidate models and then subjects them to
prediction error:

```text
symbolic hypothesis -> retrieval contradiction -> Socratic pressure -> Pauli block -> Lean failure
```

Failure is not waste. It is an error signal that becomes future memory.

#### Neuromodulatory salience

Attention should be influenced by novelty, owner-lane value, Pauli risk,
proof proximity, symbolic resonance, user priority, and failed-attempt residue.
This should be explicit scoring, not hidden model vibe.

## 4. Non-breaking metadata doctrine

The existing Hive authority ladder should be preserved:

```text
navigation
semantic
proposal
execution_intent
lean_checked
build_checked
audit_checked
promoted
```

Do not replace this ladder with labels like `symbolic_navigation` or
`common_unconscious`. Instead, add orthogonal metadata axes:

```json
{
  "authority": "semantic",
  "authority_origin": "symbolic_navigation",
  "epistemic_layer": "common_unconscious",
  "cognitive_function": "intuition",
  "symbolic_stage": "albedo",
  "pauli_status": "unaudited",
  "promotion_state": "not_allowed",
  "allowed_uses": ["retrieval_bias", "question_generation", "candidate_generation"],
  "forbidden_uses": ["proof", "promotion", "authority_gate_bypass"]
}
```

This keeps validator compatibility while giving the Hive richer cognition.

Authority:


### L5 lean_topology


Important: Lean topology helps route and retrieve. It is not proof authority by

### L6 packet_lineage

Typed theorem-factory packets and their transformations.

Typical packet chain:

```text
SourceObservationPacket
  -> SymbolicSeed / SymbolicMotifPacket
```

Authority depends on packet kind.

### L7 authority

The final gate layer.

Only wrappers/gates may write this layer:

```text
LeanVerificationPacket
BuildPacket
AuditPacket
PromotionDecisionPacket
```

Authority:

```text
lean_checked | build_checked | audit_checked | promoted
```

## 6. Packet metadata contract

Every cognitive packet should carry at least:

```json
{
  "kind": "...",
  "authority": "navigation | semantic | proposal | execution_intent | lean_checked | build_checked | audit_checked | promoted",
  "authority_origin": "source_observation | symbolic_navigation | socratic_interrogation | pauli_differentiation | lean_wrapper | build_gate | audit_gate | promotion_gate",
  "epistemic_layer": "raw_source | citation | common_unconscious | cognitive_process | semantic | lean_topology | packet_lineage | authority",
  "cognitive_function": "sensing | intuition | thinking | feeling",
  "symbolic_stage": "nigredo | albedo | citrinitas | rubedo",
  "promotion_allowed": false,
  "allowed_uses": [],
  "forbidden_uses": [],
  "parent_packet_ids": [],
  "source_refs": [],
  "artifact_paths": []
}
```

The key mechanical rule:

```text
allowed_uses and forbidden_uses are not prose.
They are policy fields that validators and importers should eventually enforce.
```

## 7. Cognitive lanes and worker roles

### SensorBee

Dominant function: sensing.

Responsibilities:

```text
collect sources
quote accurately
hash artifacts
timestamp observations
capture browser/Google AI/arXiv/repo scans
emit SourceObservationPacket
```

Forbidden:

```text
proof claims
promotion claims
free-form theorem edits
```

### IntuitionBee

Dominant function: intuition.

Responsibilities:

```text
find motifs
cluster symbolic pressure
surface analogies
propose theorem images
emit SymbolicMotifPacket, ResonanceCluster, FormulationVariant
```

Forbidden:

```text
claiming proof
claiming owner discharge
promoting symbolic resonance to truth
```

### ThinkingBee

Dominant function: thinking.

Responsibilities:

```text
normalize into Lean-facing structure
map owner files
create ExecutionIntentPacket
run deterministic wrappers when authorized
```

Forbidden:

```text
changing theorem status without gate packets
using symbolic packets as proof
```

### FeelingBee

Dominant function: feeling.

Responsibilities:

```text
rank salience
record significance
capture human priority
judge explanatory value
emit SignificancePacket or priority metadata
```

Forbidden:

```text
overriding proof/audit gates
turning beauty into theorem authority
```

### SocratesBee

Adversarial interrogator.

Responsibilities:

```text
ask destabilizing questions
extract missing hypotheses
find weakest precise formulation
emit SocraticQuestionPacket
```

### PauliBee

Strict critic.

Responsibilities:

```text
anti-inflation audit
owner/shadow separation
hidden-assumption detection
metaphor-as-theorem quarantine
emit PauliCritique
```

### BuilderBee

Surgical code worker.

Requires:

```text
ExecutionIntentPacket
```

Emits:

```text
DiffPacket / ArtifactPacket / CheckpointPacket
```

### LeanBee

Deterministic Lean wrapper lane.

Emits:

```text
LeanVerificationPacket
```

### BuildBee

Locked Lake build lane.

Emits:

```text
BuildPacket
```

### AuditBee

Semantic/Pauli gate lane.

Emits:

```text
AuditPacket
```

### PromotionBee

Admission lane.

Requires:

```text
LeanVerificationPacket + BuildPacket + AuditPacket
```

Emits:

```text
PromotionDecisionPacket
```

## 11. Hermes Swarm integration

Hermes Workspace Swarm should become the cockpit, not the proof authority.

```text
Human / Aurora
  -> Hermes Workspace Swarm cockpit
  -> SwarmBrief
  -> Hive task packet
  -> named Hermes worker profile
  -> Swarm checkpoint
  -> Hive packet lineage event
  -> Lean / Lake / Audit / Promotion gates
  -> Kanban / Reports / Inbox visible state
```

Keep two state machines separate.

Visible workflow state:

```text
backlog -> ready -> running -> review -> blocked -> done
```

Mathematical authority state:

```text
candidate
  -> retrieved
  -> formulated
  -> proposed
  -> execution_intent
  -> lean_verified
  -> build_verified
  -> audit_checked
  -> promoted | held | quarantined
```

A Kanban card can be done while a theorem candidate remains unverified.

## 14. Invariants

Hard invariants:

```text
Symbolic material may bias retrieval, generate questions, suggest candidates, and expose hidden structure.
Symbolic material may not prove, verify, build, audit, promote, or rewrite Lean truth.

A graph edge is navigation, not proof.
An embedding neighbor is context, not proof.
A Jungian motif is pressure, not proof.
A Socratic question is interrogation, not proof.
A Pauli critique is quarantine/pressure, not proof.
A Lean wrapper may emit LeanVerificationPacket.
A Lake wrapper may emit BuildPacket.
An audit gate may emit AuditPacket.
A promotion gate may emit PromotionDecisionPacket.
```

Owner/shadow invariant:

```text
shadow packets cannot discharge owner obligations without explicit bridge lineage and Lean-backed verification.
```

Authority invariant:

```text
authority is a monotone gate lattice, not a vibe.
```

## 15. Success criteria

The neural backbone is working when:

```text
every source observation is traceable to a source and capture method;
every symbolic motif is labelled as semantic/navigation material;
every Socratic question targets a packet, source, or candidate;
every Pauli critique records the blocked inflation mode;
every theorem candidate descends to owner files before proof work;
every Lean claim has LeanVerificationPacket lineage;
every build claim has BuildPacket lineage;
every promotion decision is distinct from build success;
every graph retrieval result states its authority mode;
every swarm checkpoint maps to Hive packet/event lineage;
MotherBee can explain why a task is being worked on now.
```

## 16. Final identity

The Hive is a symbolic-cognitive theorem factory.

Its unconscious generates pressure.
Its sensing lane gathers sources.
Its intuition lane finds motifs.
Its thinking lane formalizes.
Its feeling lane ranks significance.
Its Socratic conscience interrogates.
Its Pauli conscience differentiates and quarantines.
Its Lean and Lake gates verify.
Its audit gate prevents semantic inflation.
Its promotion gate admits only what survived.

This is the architecture that lets the system borrow from Jung, Pauli,
Socrates, alchemy, cognitive neurobiology, GraphRAG, and Hermes Swarm without
collapsing symbolic imagination into theorem authority.
