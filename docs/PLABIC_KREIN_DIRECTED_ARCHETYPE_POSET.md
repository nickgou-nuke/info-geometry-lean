## 3. Directed-homotopy discipline

The codebase supplies the right categorical control surface:

1. `DirectedPath` gives typed endpoints and ordered composition.
2. `DirectedChiralTwoCell` or, preferably, `DirectedPathPresentation` gives
   explicit elementary rewrites.
3. `ContextualPathRewrite` closes a declared rewrite under left and right path
   contexts.
4. `PresentedPathHomotopy.append_congr` is the required congruence theorem for
   quotient composition.
5. `ChiralDigraphHomWithCells` transports paths and declared cells between
   carriers.
6. A graph map into `prerequisiteGraph Stage` turns each directed path into a
   genuine order comparison; it does not turn a path class into proof evidence.

Therefore a future plabic path theorem must provide:

```text
plabic graph
→ directed edge/path carrier
→ declared square/face presentations
→ contextual rewrite and append-congruence proofs
→ path transport map
→ invariant-preservation theorem
```

The existing `PlabicCluster` face-weight mutation is not by itself a
`DirectedPathPresentation`. This blocks the mistaken claim that cluster
involutivity automatically gives directed path homotopy or gauge equivalence.

## 4. Epistemic compiler control plane

The mathematical poset above is compiled through the repository's independent
control poset:

```text
raw mathematical atoms
  → causal prerequisite order
  → topological schedule

raw atoms
  → owner-level propositions / evidence

(topological schedule + proof evidence)
  → kernel-certified admission
```

This is the `CompilationArchetype` order in
`Epistemology/EpistemicFunctor.lean`. Scheduling and proof evidence are
incomparable branches; neither replaces the other. Every extracted node should
also carry a `TypedArchetype` status:

- `candidate`: carrier and intended claim extracted, no proof;
- `validated`: owner/search/CAS evidence or conditional derivation exists;
- `proved`: a real proof function is attached and its transitive axioms pass
  the repository audit.

The applicable repository workflow is therefore:

```text
preserve the chat transcript
→ extract atomic definitions/equations/hypotheses
→ classify each atom
→ bind it to an owner carrier
→ add only source-supported prerequisite edges
→ schedule the finite DAG
→ attach independent proof evidence
→ run kernel/axiom/placeholder/vacuity gates
→ promote only the exact proved scope
```

`ArchetypeHomotopyFramework` supplies the final safety distinction: a path in
a prerequisite graph proves reachability, while a compiled scheduler result
proves the mapped proposition. A quotient path, a label, or a shared formula
cannot manufacture a theorem.

## 5. Corrected deliverable boundary

The chat session yields a coherent family of finite algebraic archetypes and a
useful future comparison target. It does **not** yield a theorem that plabic
networks, Krein operators, stochastic reversal, neural adjoints, and doubled
transfers are equivalent. The smallest honest next theorem is finite and
explicit: choose one common directed-edge carrier, define each transport map,
prove path-composition compatibility, and prove one commuting readout diagram.
Until those maps and laws exist, the comparison node remains
`[bucket_3_open_debt]`.
