```lean
structure HeisenbergGroup (R : Type*) (n : Type*) where
```

```lean
(p, q, z) * (p', q', z') =
(p + p', q + q', z + z' + pairing p q')
```

```lean
z + z' + (1 / 2) * (pairing p q' - pairing p' q)
```

Yes. More precisely: the Heisenberg group is the **affine/open-cell parameter space** for a larger symmetry geometry.

The clean geometric picture is:

[
\mathfrak g =
\mathfrak g_{-2}\oplus \mathfrak g_{-1}\oplus
\mathfrak g_0\oplus
\mathfrak g_1\oplus
\mathfrak g_2
]

with

[
\mathfrak n_- := \mathfrak g_{-2}\oplus \mathfrak g_{-1}.
]

The negative part (\mathfrak n_-) is Heisenberg-type when

[
[\mathfrak g_{-1},\mathfrak g_{-1}] \subseteq \mathfrak g_{-2},
\qquad
[\mathfrak g_{-2},\mathfrak g_{-1}] = 0,
\qquad
[\mathfrak g_{-2},\mathfrak g_{-2}] = 0.
]

So the Heisenberg group (N_-) is not the whole larger symmetry group. It is the **nilpotent translation chart** of a larger homogeneous/projective/contact space.

At the group level the standard model is:

[
X = G/P
]

where (G) is the larger symmetry group and (P) is the parabolic/stabilizer subgroup corresponding to

[
\mathfrak p =
\mathfrak g_0\oplus \mathfrak g_1\oplus \mathfrak g_2.
]

Then the Heisenberg group (N_-) gives the open affine chart:

[
N_- \hookrightarrow G/P.
]

That is the “parameter space” interpretation: the Heisenberg coordinates parametrize an open dense cell of the larger symmetry space, while (G) acts on its compactification/projective closure.

Your proposed map

[
P_i \mapsto J_n,\qquad Q_i \mapsto J_{-n}
]

does **not** satisfy the standard finite Heisenberg law

[
[P_i,Q_i]=K
]

unless (n=1). In the existing repository formalization, the oscillator law is

[
[J_k,J_l] =
\begin{cases}
kK & k+l=0,\
0 & \text{otherwise}.
\end{cases}
]

This is already proved as `HeisenbergAlgebra.lie_jgen`, with `kgen` centrality also present. 

So for a finite slice using arbitrary nonzero modes (m_i), the correct normalized embedding is:

[
P_i \mapsto J_{m_i},
\qquad
Q_i \mapsto m_i^{-1}J_{-m_i},
\qquad
Z \mapsto K.
]

Then

[
[J_{m_i},m_i^{-1}J_{-m_i}]
= K.
]

Also, for a multi-index finite chart, the modes must be distinct and nonzero; otherwise cross-commutators can produce unwanted central terms. The safest version is to choose positive natural modes (m_i : \mathbb N), with (0<m_i) and injective `mode`.

```lean
# Weighted projective lift of the Heisenberg parameter chart

This file packages the projective lift of the Heisenberg affine chart and
records the homogeneous weights coming from the bosonic Sugawara action.

The projective lift is not merely a set-theoretic map.  It is equipped with
weight data compatible with the operator-level theorem

  [L₀, J_n] = -n J_n.

For a finite oscillator slice with modes `mode i`, the natural weights are:

* `P_i ↦ J_{mode i}` has weight `-mode i`;
* `Q_i ↦ J_{-mode i}` has weight `mode i`;
* `Z ↦ K` has weight `0`.
-/

namespace InfoGeometry.Projective

open scoped BigOperators
open InfoGeometry.Lie
open InfoGeometry.OperatorAlgebra
open VirasoroProject

noncomputable section

variable {𝕜 : Type*} [Field 𝕜] [CharZero 𝕜]
variable {ι : Type*} [Fintype ι]
variable {V : Type*} [AddCommGroup V] [Module 𝕜 V]

/--
Mode data for a finite oscillator slice.

`mode i` is the integer oscillator mode used for the `P_i` coordinate.
The corresponding `Q_i` coordinate is represented by the opposite mode.
-/
structure HeisenbergModeWeights (ι : Type*) where
  mode : ι → ℤ

namespace HeisenbergModeWeights

/-- The conformal weight of the `P_i ↦ J_{mode i}` coordinate. -/
def pWeight (M : HeisenbergModeWeights ι) (i : ι) : ℤ :=
  -M.mode i

/-- The conformal weight of the `Q_i ↦ J_{-mode i}` coordinate. -/
def qWeight (M : HeisenbergModeWeights ι) (i : ι) : ℤ :=
  M.mode i

/-- The central coordinate has weight zero. -/
def zWeight (_M : HeisenbergModeWeights ι) : ℤ :=
  0

end HeisenbergModeWeights

/--
A weighted vector lift of the Heisenberg parameter chart.

The field `toVector` gives a nonzero vector representative for each affine
Heisenberg coordinate.  The `modeWeights` record the conformal weights
expected from the Sugawara `L₀` commutator.

This structure deliberately does not assert global projective closure yet.
It packages the affine chart and its homogeneous weight data.
-/
structure WeightedHeisenbergLift
    (𝕜 : Type*) [Field 𝕜]
    (ι : Type*) [Fintype ι]
    (V : Type*) [AddCommGroup V] [Module 𝕜 V] where

  /-- Vector representative of a Heisenberg chart point. -/
  toVector : HeisenbergParam 𝕜 ι → V

  /-- The representative is nonzero, so it defines a projective point. -/
  ne_zero : ∀ a : HeisenbergParam 𝕜 ι, toVector a ≠ 0

  /-- Oscillator mode data determining the expected homogeneous weights. -/
  modeWeights : HeisenbergModeWeights ι

namespace WeightedHeisenbergLift

/--
The projective point associated to a Heisenberg chart parameter.
-/
def projectiveMap
    (L : WeightedHeisenbergLift 𝕜 ι V) :
    HeisenbergParam 𝕜 ι → Projectivization 𝕜 V :=
  fun a => Projectivization.mk 𝕜 (L.toVector a) (L.ne_zero a)

/-- Weight of the `P_i` coordinate in the projective chart. -/
def pWeight
    (L : WeightedHeisenbergLift 𝕜 ι V) (i : ι) : ℤ :=
  L.modeWeights.pWeight i

/-- Weight of the `Q_i` coordinate in the projective chart. -/
def qWeight
    (L : WeightedHeisenbergLift 𝕜 ι V) (i : ι) : ℤ :=
  L.modeWeights.qWeight i

/-- Weight of the central coordinate. -/
def zWeight
    (L : WeightedHeisenbergLift 𝕜 ι V) : ℤ :=
  L.modeWeights.zWeight

/--
The central projective coordinate has conformal weight zero.
-/
theorem zWeight_eq_zero
    (L : WeightedHeisenbergLift 𝕜 ι V) :
    L.zWeight = 0 := by
  rfl

/--
The `P_i` and `Q_i` coordinate weights are opposite.
-/
theorem pWeight_add_qWeight
    (L : WeightedHeisenbergLift 𝕜 ι V) (i : ι) :
    L.pWeight i + L.qWeight i = 0 := by
  simp [pWeight, qWeight, HeisenbergModeWeights.pWeight,
    HeisenbergModeWeights.qWeight]

end WeightedHeisenbergLift

An operator-level realization of the weighted projective lift.

This packages the Sugawara representation data together with a weighted
Heisenberg lift.  The theorem fields record that `L₀` acts on oscillator
coordinates with the weights supplied by the mode data.
-/

  /-- The geometric projective lift. -/
  lift : WeightedHeisenbergLift 𝕜 ι V

  /-- Heisenberg oscillator operators on the representation space. -/
  heiOper : ℤ → V →ₗ[𝕜] V

  /-- Local truncation hypothesis required by the Sugawara construction. -/
  heiTrunc : ∀ v, Filter.atTop.Eventually fun l ↦ heiOper l v = 0

    ∀ k l,
      (heiOper k).commutator (heiOper l) =
        if k + l = 0 then (k : 𝕜) • 1 else 0

/-- The Sugawara `L₀` operator. -/

    (L : SugawaraWeightedHeisenbergLift 𝕜 ι V) :
    V →ₗ[𝕜] V :=
  VirasoroProject.sugawaraGen L.heiTrunc 0

/--
The operator-level theorem giving the conformal weight of oscillator mode `n`.

This is a direct wrapper around the already-proved Sugawara primary-field
commutator.
-/
theorem L0_oscillator_weight
    (L : SugawaraWeightedHeisenbergLift 𝕜 ι V)
    (n : ℤ) :
    (L.L0).commutator (L.heiOper n) =
      (-n : 𝕜) • L.heiOper n := by
  simpa [L0] using
    InfoGeometry.OperatorAlgebra.sugawara_L0_oscillator_weight
      L.heiOper L.heiTrunc L.heiComm n

/--
The central operator has zero conformal weight.
-/
theorem L0_center_weight_zero
    (L : SugawaraWeightedHeisenbergLift 𝕜 ι V) :
    (L.L0).commutator (1 : V →ₗ[𝕜] V) = 0 := by
  simpa [L0] using
    InfoGeometry.OperatorAlgebra.sugawara_commutator_identity_zero
      L.heiOper L.heiTrunc 0

/--
The recorded projective `P_i` weight agrees with the Sugawara oscillator
weight of `J_{mode i}`.
-/
theorem pWeight_matches_sugawara
    (L : SugawaraWeightedHeisenbergLift 𝕜 ι V)
    (i : ι) :
    L.lift.pWeight i = -L.lift.modeWeights.mode i := by
  rfl

/--
The recorded projective `Q_i` weight agrees with the Sugawara oscillator
weight of `J_{-mode i}`.
-/
theorem qWeight_matches_sugawara
    (L : SugawaraWeightedHeisenbergLift 𝕜 ι V)

The projective map associated to the weighted Sugawara-Heisenberg lift.

    HeisenbergParam 𝕜 ι → Projectivization 𝕜 V :=
  L.lift.projectiveMap

end SugawaraWeightedHeisenbergLift

end

end InfoGeometry.Projective
```

```lean
      w ⟨i, h⟩
    else
      b

  have hx' := hx ⟨i, Nat.lt_trans i.isLt (Nat.lt_succ_self n)⟩
```

```lean
The normalizing scale should later be chosen so that `scale² * coeff = 1`.
-/
structure SuperStructureFactor
    (𝕜 : Type*) [Field 𝕜] [CharZero 𝕜]
    (W : Type*) [AddCommGroup W] [Module 𝕜 W] where

  parityA : SuperParity
  parityB : SuperParity

  A : W →ₗ[𝕜] W
  B : W →ₗ[𝕜] W

  /-- Canonical target operator, usually `1` or a central current. -/
  target : W →ₗ[𝕜] W

  /-- Raw coefficient before normalization. -/
  coeff : 𝕜

  coeff_ne_zero : coeff ≠ 0

  /-- Raw structure relation. -/
  raw_relation :
    superBracket parityA parityB A B = coeff • target

namespace SuperStructureFactor

variable (D : SuperDilaton 𝕜)
variable (S : SuperStructureFactor 𝕜 W)

/-- Normalized first operator. -/
def normalizedA (n : ℤ) : W →ₗ[𝕜] W :=
  (D.scale n : 𝕜) • S.A

/-- Normalized second operator. -/
def normalizedB (n : ℤ) : W →ₗ[𝕜] W :=
  (D.scale n : 𝕜) • S.B

/--
Scale condition saying the normalized structure coefficient is `1`.

Since both operators are scaled, the bracket is scaled by `scale²`.
-/
def IsNormalizedToOn (n : ℤ) : Prop :=
  ((D.scale n : 𝕜) * (D.scale n : 𝕜)) * S.coeff = 1

/--
Bilinearity of the superbracket under common scalar scaling.

This is the algebraic mechanism behind scale normalization.
-/
theorem superBracket_scaled
    (n : ℤ) :
    superBracket S.parityA S.parityB
      (S.normalizedA D n)
      (S.normalizedB D n)
      =
    (((D.scale n : 𝕜) * (D.scale n : 𝕜)) •
      superBracket S.parityA S.parityB S.A S.B) := by
  ext w
  simp [normalizedA, normalizedB, superBracket, SuperParity.sign,
    mul_assoc, mul_comm, mul_left_comm]

/--
Meaningful normalization theorem.

If `scale² * coeff = 1`, then the normalized superbracket equals the canonical
target operator.
-/
theorem normalized_superBracket_eq_target
    (n : ℤ)
    (h_norm : S.IsNormalizedToOn D n) :
    superBracket S.parityA S.parityB
      (S.normalizedA D n)
      (S.normalizedB D n)
      =
    S.target := by
  rw [S.superBracket_scaled D n]
  rw [S.raw_relation]
  ext w
  simp [IsNormalizedToOn] at h_norm
  simp [smul_smul, h_norm]

end SuperStructureFactor

This is the fermionic/odd-odd case.  The target is usually the identity.
```

What it does **not** claim:

It does not claim the same Clifford pair gives a bosonic CCR. That remains false in general. It also does not claim a super-Kähler manifold. The file proves super-graded normalization of operator brackets. To formalize super-Kähler geometry, add a separate structure with graded complex structure, metric, symplectic form, and compatibility axioms.

```lean
# Möbius scale closure for a five-graded algebra

This file packages the extra data needed to treat a five-graded algebra as a
Möbius/contact closure.

A `FiveGradedAlgebra` by itself gives bracket compatibility.  It does not
automatically provide a Weyl/Möbius inversion swapping the lowest and highest

namespace InfoGeometry.Projective

open scoped LinearAlgebra.Projectivization
open VirasoroProject

noncomputable section

variable {𝕜 : Type*} [Field 𝕜] [CharZero 𝕜]
variable {G : FiveGradedAlgebra 𝕜}
variable [NoZeroSMulDivisors 𝕜 G.algebra]

attribute [local instance] VirasoroProject.FiveGradedAlgebra.instLieRing
attribute [local instance] VirasoroProject.FiveGradedAlgebra.instLieAlgebra

/--
An involutive Möbius/Weyl-type inversion for a five-graded algebra.

The grading convention is:

* `grade 0 = g₋₂`;
* `grade 1 = g₋₁`;
* `grade 2 = g₀`;
* `grade 3 = g₊₁`;
* `grade 4 = g₊₂`.
-/
structure FiveGradedMoebiusInversion
    (G : FiveGradedAlgebra 𝕜) where

  /-- The inversion as a linear equivalence. -/
  invOp : G.algebra ≃ₗ[𝕜] G.algebra

  /-- Lowest grade maps to highest grade. -/
  map_grade0_to_grade4 :
    ∀ x : G.algebra, x ∈ G.grade 0 → invOp x ∈ G.grade 4

  /-- Highest grade maps to lowest grade. -/
  map_grade4_to_grade0 :
    ∀ x : G.algebra, x ∈ G.grade 4 → invOp x ∈ G.grade 0

  /-- The inversion is involutive. -/
  involutive :
    ∀ x : G.algebra, invOp (invOp x) = x

namespace FiveGradedMoebiusInversion

variable (M : FiveGradedMoebiusInversion G)

/--
A nonzero point in the highest grade is sent to a nonzero point in the lowest
grade.
-/
theorem grade4_to_grade0_nonzero
    {x : G.algebra} (hx : x ∈ G.grade 4) (hnz : x ≠ 0) :
    M.invOp x ∈ G.grade 0 ∧ M.invOp x ≠ 0 := by
  constructor
  · exact M.map_grade4_to_grade0 x hx
  · intro hzero
    apply hnz
    have h := congrArg M.invOp hzero
    simpa [M.involutive] using h

/--
The Möbius inversion sends a projective point at infinity to a projective point
in the lowest-grade chart.

This is a grade-transfer statement, not yet a statement that it returns to a
specific original point.
-/
theorem infinity_maps_to_zero_chart
    {x : G.algebra} (hx : x ∈ G.grade 4) (hnz : x ≠ 0) :
    ∃ (y : G.algebra) (hy : y ∈ G.grade 0) (hynz : y ≠ 0),
      Projectivization.mk 𝕜 (M.invOp x)
          (M.grade4_to_grade0_nonzero hx hnz).2
        =
      Projectivization.mk 𝕜 y hynz := by
  refine ⟨M.invOp x, (M.grade4_to_grade0_nonzero hx hnz).1,
    (M.grade4_to_grade0_nonzero hx hnz).2, rfl⟩

end FiveGradedMoebiusInversion

A grade `+1` chiral flow.

Repeated bracketing by `raise` moves grade `0` upward through the five-grading.

structure ChiralRaisingFlow
    (G : FiveGradedAlgebra 𝕜) where
  raise : G.algebra
  raise_mem : raise ∈ G.grade 3

namespace ChiralRaisingFlow

variable (F : ChiralRaisingFlow G)

/-- Iterated adjoint action. -/
def iterAd : ℕ → G.algebra → G.algebra
  | 0, x => x
  | Nat.succ n, x => ⁅F.raise, iterAd n x⁆

/--
Four raising steps take grade `0` to grade `4`.

This follows from five-grading compatibility.
-/
theorem iterAd_four_mem_grade4
    {x : G.algebra} (hx : x ∈ G.grade 0) :
    F.iterAd 4 x ∈ G.grade 4 := by
  -- Step 1: grade 0 -> grade 1.
  have h1 : F.iterAd 1 x ∈ G.grade 1 := by
    dsimp [iterAd]
    exact
      G.bracket_compat 3 0 1 (by decide)
        F.raise F.raise_mem x hx

  -- Step 2: grade 1 -> grade 2.
  have h2 : F.iterAd 2 x ∈ G.grade 2 := by
    dsimp [iterAd]
    exact
      G.bracket_compat 3 1 2 (by decide)
        F.raise F.raise_mem (F.iterAd 1 x) h1

  -- Step 3: grade 2 -> grade 3.
  have h3 : F.iterAd 3 x ∈ G.grade 3 := by
    dsimp [iterAd]
    exact
      G.bracket_compat 3 2 3 (by decide)
        F.raise F.raise_mem (F.iterAd 2 x) h2

  -- Step 4: grade 3 -> grade 4.
  dsimp [iterAd]
  exact
    G.bracket_compat 3 3 4 (by decide)
      F.raise F.raise_mem (F.iterAd 3 x) h3

end ChiralRaisingFlow

/--
A certified pole bridge.

This is the extra datum needed to say that raising from the lowest pole to the
highest pole and then applying Möbius inversion returns projectively to the
original point.
-/
structure CertifiedMoebiusPoleBridge
    (G : FiveGradedAlgebra 𝕜) where

  inversion : FiveGradedMoebiusInversion (𝕜 := 𝕜) G
  flow : ChiralRaisingFlow (𝕜 := 𝕜) G

  /--
  The four-step raised point is nonzero whenever the input point is nonzero.
  This is not automatic from the grading alone.
  -/
  four_step_nonzero :
    ∀ x : G.algebra, x ∈ G.grade 0 → x ≠ 0 →
      flow.iterAd 4 x ≠ 0

  /--
  The genuine pole-return condition.

  This is the data the draft tried to prove from `bracket_compat`, but it is
  not derivable without a concrete representation or additional axioms.
  -/
  pole_return_projective :
    ∀ x : G.algebra, x ∈ G.grade 0 → x ≠ 0 →
      ∃ c : 𝕜ˣ,
        inversion.invOp (flow.iterAd 4 x) = (c : 𝕜) • x

namespace CertifiedMoebiusPoleBridge

variable (B : CertifiedMoebiusPoleBridge (𝕜 := 𝕜) G)

/--
The certified bridge returns the raised-and-inverted point to the original
projective point.
-/
theorem pole_return_projective_point
    {x : G.algebra} (hx : x ∈ G.grade 0) (hnz : x ≠ 0) :
    Projectivization.mk 𝕜
        (B.inversion.invOp (B.flow.iterAd 4 x))
        (by
          have h4nz := B.four_step_nonzero x hx hnz
          intro hzero
          apply h4nz
          have h := congrArg B.inversion.invOp hzero
          simpa [B.inversion.involutive] using h)
      =
    Projectivization.mk 𝕜 x hnz := by
  rcases B.pole_return_projective x hx hnz with ⟨c, hc⟩
  apply
    (Projectivization.mk_eq_mk_iff 𝕜
      (B.inversion.invOp (B.flow.iterAd 4 x))
      x
      (by
        have h4nz := B.four_step_nonzero x hx hnz
        intro hzero
        apply h4nz
        have h := congrArg B.inversion.invOp hzero
        simpa [B.inversion.involutive] using h)
      hnz).2
  exact ⟨c, hc⟩

end CertifiedMoebiusPoleBridge

end
```
