LeanTrail is the semantic explorer lane for this repository.
It is Sourcetrail-style in UX, but Lean-native in evidence: it consumes DAG and
process-flow artifacts produced from elaborated Lean data.

### Invalidation Strategy

- local/dev: incremental snapshot patching (`--incremental`) prunes and rebuilds
  only impacted module neighborhoods;
- CI/release: full snapshot rebuild for deterministic full-graph coverage.

### Memory-Carrier Adapters

LeanTrail now supports external memory carriers while keeping canonical truth in
the Lean snapshot lane:

- GraphML (`graph_snapshot.graphml`)
- Neo4j CSV (`neo4j/nodes.csv`, `neo4j/edges.csv`, `neo4j/metadata.json`)
- Arango JSON (`arango/ig_nodes.jsonl`, `arango/ig_edges.jsonl`, `arango/metadata.json`)

Exports are generated by:

- `tools/leantrail/export.py`
- `lake script run leantrailExport ...`

Conformance is checked by:

- `tools/leantrail/conformance.py`
- `lake script run leantrailConformance ...`

The conformance gate compares canonical snapshot vs exported/reimported carrier
on:
- count drift (nodes/edges),
- SCC signature,
- path parity on canonical queries,
- coherence/holonomy hotspot overlap.

## Contract

- graph shape is diagnostic evidence, not theorem truth;
- Lean kernel remains closure authority;
- bridge claims emitted from LeanTrail must resolve as `equivalence`,
  `obstruction`, or `discard` packets.
- holonomy scoring is an explorer diagnostic, not a proof-validity metric.

## HolonomyAuditor (MVP)

LeanTrail now includes a first holonomy lane:

- API: `GET /holonomy/hotspots`
- Infra: `tools/infra/holonomy_auditor.py`
- Artifact: `artifacts/leantrail/holonomy_report.json`

Score model:

`holonomy_score = alpha * tactic_steps + beta * context_expansion + gamma * metavariable_flux`

Data source policy:

- prefer explicit telemetry fields attached to declaration attrs;
- fallback to structural proxies when telemetry is unavailable.
