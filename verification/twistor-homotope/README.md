# Ordered homotopes and native twistor invariants

This focused Lake project checks the repository's exact source with its
unchanged Lean and Mathlib pins. The mathematical scope and the corrections
to the submitted stream are in
[`TWISTOR_HOMOTOPE_INVARIANTS_CONTRACT.md`](../../docs/TWISTOR_HOMOTOPE_INVARIANTS_CONTRACT.md).
The original intake is preserved in `docs/intake` with its SHA256 recorded
in that contract.

## Commands

From the repository root, with the pinned Elan toolchain on `PATH` and the
repository's `jsonschema==4.23.0` Python dependency installed:

```bash
python3 verification/twistor-homotope/check.py exe cache get
python3 verification/twistor-homotope/check.py build
python3 verification/twistor-homotope/check.py env python3 "$PWD/verification/twistor-homotope/verify.py"
```

The wrapper validates workspace integrity and owns the shared build lock.
The complete verification driver invokes subordinate commands sequentially
without reacquiring that lock. Do not run it directly beside another build.
It performs:

- A focused build of all six mathematical owners and the audit.
- A separate fresh Lean execution of `TwistorHomotopeAudit.lean`.
- Complete owner/declaration and named-theorem membership checks.
- Strict OpenGauss screening and refutation.
- Static Gate 4, explicitly recorded as not a kernel check.
- Regex vacuity scanning, retaining every raw result. Only the exact findings
  and source hashes in `VACUITY_REVIEW.json` receive the documented mathematical
  classification; all unreviewed findings fail the driver.
- Scoped whitespace, dependency pin, source fingerprint, and compiled-artifact checks.
- Exact committed-source equality, reviewed root-control references, and unchanged
  dependency worktrees. Every protected source and root control must remain
  unchanged throughout the run.

Logs and `checks.json` are written under `logs/` and retained by the GitHub
workflow as an artifact. A successful driver run records `CHECKS_PASSED`;
independent QA still needs to rerun and inspect the frozen workflow before a
separate acceptance claim is made.

## Reviewed root controls

Fourteen root controls remain byte-for-byte bound to the original implementation
base, `c143c264bc18bbf41d692be4e270b5b7f7405702`. The sole updated reference is
`tools/infra/opengauss_screener.py`, pinned to
`8b270668ea5ce0f0361f606ed09dc94f28922a78` (SHA256
`10d3ec0a64ef37359598aff9c8ee709490a615ecbe13ca1b857a99006b7bd422`).
That revision adds a token boundary to the T16 `commutator` pattern: a projection
of a named commutator matrix is not a scalar commutator. The existing regression
suite retains positive detection of scalar projections inside a commutator and
adds coverage of the identifier-prefix false positive.

The verifier still requires each root control to equal both its committed `HEAD`
source and its exact reviewed revision. A different committed screener change,
an uncommitted change, or a change to another control fails verification. The
before/after fingerprint checks still cover all fifteen controls. Regression
tests in `tests/test_twistor_homotope_controls.py` exercise these boundaries using
temporary Git repositories; the projective-rank workflow runs them alongside the
OpenGauss regressions.

The v2 execution report records every control's reference revision and SHA256,
and separates the fourteen unchanged controls from the one reviewed update.
Historical `RESULTS.md` and hosted QA receipts describe their original revisions
and have not been rewritten as evidence for this migration.

## Mathematical boundaries

The generic homotope remains noncommutative. Its concrete witness uses the
existing null-twistor moment matrices and a square-zero kernel. The Gram and
mass readouts use the existing complex twistor packets; the algebraic
independence theorem concerns real-valued functions on those packets.

The traceless quadratic form has positive half-trace normalization. The
Cayley action uses the existing row-mixing/column-transpose convention.
The integer recurrence is generated by its actual two-mode transition matrix;
this alone does not identify its values with Clifford-space dimensions.

This project does not certify the root optional path dependencies, unrelated
default targets, whole-repository debt, or physical/group-classification
claims. See [`RESULTS.md`](RESULTS.md) for the actual observed status.
