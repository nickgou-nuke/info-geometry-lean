# Jung–Pauli Split-Step Hive Blueprint

Status: proposed architecture blueprint
Date: 2026-04-24
Scope: recurrent symbolic cultivation, packet distillation, graph memory, and Lean-facing formalization inside the Hermes Hive.

## 1. Thesis

The Hive should not operate by immediate rejection of weak symbolic material.

It should operate by **split-step cultivation**:

```text
Jung step  -> semantic excitation / reformulation / symbolic spreading
Pauli step -> distinction / sharpening / anti-inflation / admissibility pressure
```

repeated until a sufficiently stable invariant emerges and can be translated into
formal targets.

Lean remains the final survival authority.

## 2. Canonical operator picture

```text
seed / obstruction / black-book fragment / dialogue / DAG anomaly
  -> Jung excitation
  -> Jung resonance family
  -> Pauli differentiation
  -> invariant extraction
  -> packet legalization
  -> Lean-facing translation
  -> kernel/build/audit gates
  -> promotion OR residue return
```

The Hive is therefore not a one-pass theorem proposer.
It is a **recurrent symbolic propagation system** in a nonlinear medium.

## 3. Physical analogy

The best working analogy is a split-step solution of wave propagation in a
nonlinear medium.

### Jung step
Analog of:
- diffraction
- diffusion
- nonlinear semantic spreading
- excitation of latent resonant modes

Operational meaning:
- reformulate the same seed many ways
- sample nearby symbolic basins
- surface hidden analogies
- generate alternate theorem phrasings
- generate geometric / categorical / operatorial / Lean-facing paraphrases

### Pauli step
Analog of:
- phase correction
- focusing
- mode separation
- exclusion against incoherent collapse

Operational meaning:
- compare the family of Jung outputs
- sharpen distinctions
- suppress decorative restatement
- identify incompatible branches
- extract stable invariants
- enforce admissibility pressure before expensive formalization

### Lean step
Analog of:
- hard boundary condition
- projection onto formal survivability

Operational meaning:
- elaboration
- local theorem probing
- targeted build
- proof-state contact
- formal survival or failure

## 4. Doctrine

### 4.1 Primary law

**Do not kill the weak signal too early.**

A candidate may be semantically weak in its first expression yet carry a strong
latent invariant that only appears after recurrent reshaping.

### 4.2 Secondary law

**Not every excited signal deserves canonical formalization.**

Cultivation precedes rejection, but rejection is still necessary at the
admission boundary to preserve theorem-factory resources.

### 4.3 Final law

**The Black Book generates pressure, packets legalize targets, Lean decides what survives.**

## 5. Layered architecture

## Layer 0 — runtime substrate

Runtime envelope:
- OpenClaw / Hermes / OpenShell / local services
- persistent workers
- bounded loops
- sandboxed execution where appropriate
- tool and transport policy

This layer governs execution safety and continuity, not theorem truth.

## Layer 1 — memory substrate

Canonical memory should be split into:

1. **Raw symbolic reservoir**
   - black books
   - dialogues
   - notes
   - residue texts

2. **Structured graph memory**
   - ArangoDB as the backbone
   - typed nodes and edges for epistemic transformation

3. **Operational event log**
   - runs
   - prompts
   - packet revisions
   - build outcomes
   - audit outcomes

The graph is the enduring semantic spine. Chat history is not.

## Layer 2 — recurrent cultivation loop

Each seed enters a bounded recurrence:

1. ingest seed
2. Jung excitation pass
3. variant-family collection
4. Pauli differentiation pass
5. invariant extraction
6. synthesis / merge
7. packet legalization
8. Lean-facing translation
9. small formal probe
10. either iterate, promote, or return residue

This loop must be bounded per run, but unbounded across history.

## Layer 3 — worker castes

### Mother bee: HermesHive
Responsibilities:
- route work
- enforce doctrine
- bind memory and skill loading
- maintain lineage and packet discipline
- manage recurrence limits and escalation gates

HermesHive governs passage; it does not certify theorem truth.

### Jung bees
Roles:
- excitation
- symbolic expansion
- bridge surfacing
- reformulation families
- alternate representational rendering

Likely embodiments:
- high-temperature sidecars
- symbolic planners
- multimodal merger models when available

### Pauli bees
Roles:
- distinction
- invariant sharpening
- anti-inflation
- novelty defense drafting
- branch separation

Important: Pauli bees should not police emergence at the first moment of birth.
They operate after a formulation family exists.

### Translation bees
Roles:
- turn invariant structures into packet fields
- propose namespaces, signatures, dependencies, theorem families
- map prose and symbolic structures into Lean-facing forms

### Proof bees
Roles:
- local probing
- proof-state contact
- tactic search
- retrieval of nearby lemmas

Lean remains final proof authority.

### Audit bees
Roles:
- legality checks
- conservative review
- architecture conformance
- duplication and promotion review

### Build / Promotion bees
Roles:
- run executable gates
- decide canonical admission
- write durable state transitions

## 8. The recurrent loop in detail

## 8.1 Seed intake
Sources may include:
- black-book fragments
- Socratic dialogue passages
- formalization failures
- DAG discontinuities
- audit objections
- operator prompts
- Alexandria/arXiv extraction outputs

Each intake event creates a `symbolic_seed` and a lineage id.

## 8.2 Jung excitation pass
A Jung pass should:
- preserve source contact
- reformulate without premature narrowing
- produce multiple candidate views
- allow category shifts of representation
- allow theoretical deepening
- allow alternate theorem phrasing families

A Jung pass should not claim theorem truth.

## 8.3 Resonance clustering
The system compares the family of outputs and detects:
- recurring motifs
- recurring operators
- recurring dependency claims
- recurring signature shapes
- recurring obstructions

What repeats across variation is the first approximation to invariant content.

## 8.4 Pauli differentiation
The Pauli pass should:
- separate genuinely distinct readings
- identify internal contradiction
- collapse decorative duplication
- mark branches that are only terminological restatement
- mark branches that fail to project into formal targets

This is shaping, not merely negation.

## 8.5 Invariant extraction
The system extracts one or more `InvariantDraft`s:
- stable structural relation
- candidate theorem shape
- candidate definitional need
- candidate bridge relation
- candidate lemma family

## 8.6 Translation
Translation bees convert invariants into:
- namespace proposals
- Lean-facing signatures
- dependency guesses
- nearby existing theorem anchors
- minimal executable formal probes

## 8.7 Formal probe
Before full expensive formalization, the system should run a minimal probe:
- token-free REPL/kernel contact when available
- target import checking
- existence of referenced objects
- local theorem-shape plausibility
- targeted build surface

## 8.8 Outcome routing
Outcomes:
- `iterate_more`
- `legalize_packet`
- `request_proof_search`
- `request_build`
- `promote`
- `return_to_residue`

## 9. Admission boundary

The harsh tests belong here, not at first emergence.

Before expensive formalization, evaluate:
- is there a stable invariant across formulations?
- does the candidate project to a minimally coherent formal target?
- is the novelty defense non-empty?
- does it attach to repository geometry?
- is the expected formalization cost justified?

If no, return to cultivation or residue.

## 10. Residue doctrine

Failure is not deletion.
Failure is structured return.

Residue should be classified as:
- `symbolic_overheat`
- `formal_target_missing`
- `repo_anchor_missing`
- `novelty_collapse`
- `proof_obstruction`
- `translation_failure`
- `architecture_illegality`
- `transport_failure`

Every residue packet should link back into the graph and be revivable as future pressure.

## 11. Skill doctrine

Skill creation belongs inside the loop but under bounded law.

Allowed:
- provisional skills
- local templates
- role-specific reshaping prompts
- packet translators
- clustering and merge utilities

Not allowed:
- hidden authority bypass
- unlogged mutation of canonical theorem surfaces
- direct canonization by prompt output alone

## 12. Sandboxes and cluster use

OpenShell / NemoClaw should host risky or stateful worker execution where useful:
- long-running worker bees
- external retrieval or API lanes
- experimental multimodal merging
- isolated translation/prover tasks

But the cluster is substrate only.
It is not theorem authority.

Canonical stack:

```text
OpenShell / NemoClaw
  -> HermesHive
  -> Jung / Pauli / Translation / Proof / Audit bees
  -> Arango graph + packet stores
  -> Lean / build / audit / promotion gates
```

## 13. Minimal implementation plan

### Phase A — schema first
- define Arango collections and edges
- define packet JSON schemas
- define lineage ids and run ids
- define residue taxonomy

### Phase B — bounded recurrent loop
- extend the current bounded runner
- add Jung and Pauli stages explicitly
- write outputs to typed graph objects and run artifacts

### Phase C — translation surface
- add translation packets and minimal Lean probes
- connect to existing DAG/gravity context tooling
- enforce target import and namespace checks

### Phase D — authority gates
- connect proof, build, audit, promotion paths
- add durable state transitions in graph and artifacts

### Phase E — sandboxed worker ecology
- place selected bees into OpenShell-backed cells
- maintain one canonical orchestrator lineage above them

## 14. Non-negotiables

- Lean is final truth authority.
- Arango is the canonical structured memory spine.
- The Black Book is a discovery reservoir, not a direct authority surface.
- Packets legalize what symbolic emergence may target.
- Pauli pressure sharpens after formulation families exist.
- Residue is preserved as future fuel.
- Expensive formalization requires explicit admission.
