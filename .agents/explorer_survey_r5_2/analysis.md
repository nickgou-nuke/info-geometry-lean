## 1. Executive Summary & Quantitative Landscape

A repository-wide audit reveals **587 Lean 4 source files** containing **3,059 occurrences** of `native_decide`.

### The `native_decide` Bottleneck Problem
In Lean 4, `native_decide` compiles Lean expressions to native C code and executes the compiled binary or VM evaluator during elaboration to produce a proof via the `Lean.ofReduceBool` trust rule. While effective for prototyping, in a 24,000-file repository it introduces severe architectural and performance penalties:
1. **Elaboration Latency & Resource Spikes**: Invoking native compilation on hundreds of small matrix multiplications or Fibonacci terms causes massive compiler memory footprint and CPU hangs. For example, during our investigation, `lean lean/InfoGeometry/Canonical/ThreeColorNativeBracketTable.lean` was observed consuming 78% CPU and 4.8 GB of RAM (59% of system memory) for over 3.5 minutes on a single file due to `native_decide` elaboration.
2. **Kernel Purity & Trust Bypass**: Proofs generated by `native_decide` depend on the C code generator rather than pure Lean kernel reduction (`rfl` / definitional equality), bypassing the formal kernel guarantees.
3. **Non-modular Redundancy**: The exact same algebraic identities (e.g. unit conjugation of generalized inverses, Cayley-Hamilton trace recurrences, nilpotency of shear matrices) are repeatedly re-verified via brute-force VM execution rather than being factored into O(1) categorical/structural theorems.

## 4. CAS Certificate Architecture (SymPy / Sage)

To support the refactored Lean files, we define the standard CAS Certificate Pipeline:

### 4.1 Schema for Rational Matrix Certificates
For any rational matrix packet $(A, X) \in \mathbb{Q}^{m \times n} \times \mathbb{Q}^{n \times m}$ (e.g. Moore-Penrose, Drazin, weak Drazin):
```json
{
  "name": "packetName",
  "rows": 3,
  "cols": 3,
  "dA": 1,
  "dX": 2,
  "scale": 2,
  "A": [["2", "0", "0"], ["0", "0", "1"], ["0", "0", "0"]],
  "X": [["1/2", "0", "0"], ["0", "0", "0"], ["0", "0", "0"]],
  "M_A": [[2, 0, 0], [0, 0, 1], [0, 0, 0]],
  "M_X": [[1, 0, 0], [0, 0, 0], [0, 0, 0]],
  "verified_rational_equations": true,
  "verified_integer_cleared": true
}
```

### 4.2 Integer-Cleared Scaling Law
For Moore-Penrose and Drazin relations, denominators are cleared by finding:
$$d_A = \mathrm{lcm}_{i,j}(\mathrm{denom}(A_{i,j})), \quad d_X = \mathrm{lcm}_{i,j}(\mathrm{denom}(X_{i,j}))$$
Setting $M_A = d_A A \in \mathbb{Z}^{m \times n}$ and $M_X = d_X X \in \mathbb{Z}^{n \times m}$, the equations scale purely in $\mathbb{Z}$:
$$M_A M_X M_A = (d_A d_X) M_A$$
$$M_X M_A M_X = (d_A d_X) M_X$$
$$(M_A M_X)^T = M_A M_X$$
This guarantees that all symbolic intermediate calculations in Python/Sage avoid floating-point inaccuracies and map directly to Lean integer arithmetic.

## 5. Lean 4 O(1) Proof Engineering Rules

All refactored proofs must satisfy the following strict requirements:

| Rule | Description |
|:---|:---|
| **R1: Zero `native_decide`** | Every `native_decide` is replaced by `rfl`, `decide`, finite case extensionality, or structural lemma application. |

| **R3: 100% Proposition Fidelity** | The theorem declaration and proposition type must remain 100% identical (character-level proposition match). |
| **R4: Structural / Categorical Factoring** | When an identity holds for a class of objects (e.g. unit conjugation $u A u^{-1}$ or Cayley-Hamilton recurrence), factor it into a reusable lemma rather than evaluating entry-by-entry. |
| **R5: Subagent Sandbox Isolation** | All refactoring work must occur inside `.agents/sandbox_<name>/` and compile cleanly before promotion. |
