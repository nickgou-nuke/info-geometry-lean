# 67. The External Analogy Doctrine

*Date: April 14, 2026*  
*Context: LLM spin-glass analogies, mcbal references, and owner-discipline hardening*

## Core Decision

The Spire does **not** depend on external analogy frameworks for canonical validity.

External work (including mcbal's transformer/spin-system intuition) is treated with respect, but remains:

- a comparative lens,
- a heuristic generator,
- a stress test for language and bridges,
- never an owner of repository truth.

Canonical truth remains Lean-native and owner-first.

## What Is Accepted

External analogies are allowed to:

- inspire candidate structures,
- suggest correspondence maps,
- motivate experiments and packets,
- improve explanatory language for outreach.

## What Is Not Accepted

External analogies are not allowed to:

- define owner symbols,
- set theorem semantics,
- bypass repo-native mapping,
- promote themselves into canonical lanes by rhetoric.

## Formal Policy Surface

Injection governance now encodes this doctrine explicitly:

- packets carry an `authority_tier`,
- `external_analogy` packets may be researched and translated,
- automation blocks `external_analogy` promotion to `gated` and `accepted`.

This keeps ideation open while protecting canonical integrity.

## Canonical Translation Rule

If an external idea survives contact with the repo, it must be rewritten into existing owner language:

- Drazin/projector lanes,
- modular/transport lanes,
- certified operator bridges,
- Lean-checked theorem surfaces.

No external label is admitted as canon until it is expressed and verified in repo-native symbols.

## Immediate Example

`Softmax ~ KMS/Gibbs` is accepted only as a **repo-native bridge theorem family** built over existing thermodynamic router identities, not as imported metaphysics.

The accepted object is the compiled bridge.
The external story remains commentary.

## Final Rule

Respect without dependency.

The Spire may converse with external theory indefinitely;  
it must be founded only on what it proves.
