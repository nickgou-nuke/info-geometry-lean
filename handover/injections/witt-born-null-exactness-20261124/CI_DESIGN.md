## Dependency layout: why a fresh preparation step is required

The checker accepts a flat `--packages` directory and searches `*/.lake/build/lib/lean` directly beneath it. A native Mathlib checkout instead materializes its dependencies under `mathlib/.lake/packages`. Passing either directory alone omits a required part of the search path.

The candidate therefore:

1. Clones exactly the root-pinned Mathlib revision into a fresh job-owned `RUNNER_TEMP/zorn-witt-native-packages/mathlib` checkout.
2. Requires Mathlib's toolchain to match the repository and all native dependency URL/revision pairs to match the root manifest.
3. Uses the current checker's import closure to request precisely its direct native imports and their transitive cache dependencies. Mathlib's pinned `Cache/Main.lean` documents module-name arguments for `cache get` and confirms that no arguments would request the umbrella Mathlib cache; the workflow always supplies the discovered imports.
4. Runs the pinned native `lake -d <mathlib> exe cache get ...` under the repository's maintained **exclusive** build lock, reusing `checker.execute` for child lifecycle handling and logs.
5. Rejects manifest drift or dirty/mismatched package checkouts after hydration.
6. Moves each fresh nested dependency checkout to a sibling of Mathlib. This is a same-filesystem rename inside the job-owned fresh directory, preserves its Git metadata/artifacts, creates no symlink, and makes no duplicate build-cache copy.
7. Rechecks every moved Git checkout, then calls the same `checker.environment` used by validation. That check binds the real compiler binary hash/version, root manifest, source revisions, dependency search paths, and verifier hash.

## Validation and receipts

After cache preparation, the workflow runs the maintained checker sequentially with:

1. `--suite supplied-zorn-counterexample`;
2. `--suite witt-born-null-exactness`.

Neither command uses `--targets` or disables audits. Both retain the selected suite's automatic audit and `OWNED` warnings-as-errors policy. The checker continues to own exact source snapshots, package checks, shared-lock serialization, and transitive axiom audit. A final receipt check requires both statuses to be `compiled`, `audit_expected = true`, and `audit_status = passed`, then rechecks their source hashes.

An `always()` step copies only logs, JSON receipts, audit source, and checker source into a visible `native-evidence` directory before uploading it. This avoids silently losing receipts under hidden `.lake` directories and avoids uploading binary caches or unrelated files. Failed compilation/cache steps retain nonzero job status; evidence collection does not mark them successful.

The cache preparation and full proof suite share one GitHub job and run sequentially. Existing repository gates and workflows are unchanged, and this scoped result would not certify the repository's unrelated optional packages or complete root `InfoGeometry.All` build.
