# 189. The Transformer Model of the Hive and the Arnold-Arango Surrogate

The Hive is not only a queue of agents.

It is a transformer-shaped theorem organism whose memory is split between two
very different reservoirs:

- the small, exact, topologically protected universe of compiled Lean truth,
  indexed through Arango;
- the vast common unconscious of language, analogy, mathematics, physics, and
  latent association carried by large language models.

The bridge between them cannot be a naked prompt.

The bridge must be an overlay.

## 1. The Arango Universe

Arango is the small universe.

It contains the theorem graph, declaration graph, SCC quotient, representation
depth labels, process-flow edges, defect tags, Hodge summaries, Dirac sparse
entries, chiral gradings, semantic-flow reports, and gravitational context
packets.

It is not the Lean kernel.

It is a derived memory carrier over Lean truth.

But it is exact enough to have topology.

Its nodes have mass.

Its edges carry flow.

Its layers form a representation ladder:

```text
count -> projective -> operator -> krein -> transport -> thermo
```

Its defects are not merely bugs.

They are curvature.

They show where the symbolic flow fails to factor locally, where a bridge jumps
across representation depth, where a shadow pretends to be an owner, or where a
remote theorem has been attached without a lawful corridor.

The graph is therefore not just storage.

It is a thermodynamic object.

## 2. Graph Thermodynamics

The graph already has thermodynamic readings.

There is transport credit.

There is defect debt.

There is polarity.

There is chirality sign.

There is diffusion.

There is entropy production over asymmetric edge rates.

There is harmonic mass inside loops.

There is holonomy.

There is obstruction potential.

This means the theorem graph can be read as a finite non-equilibrium
information system:

```text
nodes      = theorem states / declarations / packets
edges      = dependency flow / transport / witness descent
rates      = graph-theoretic motion weights
defects    = entropy-producing obstructions
cycles     = holonomy-bearing semantic loops
layers     = representation strata
```

The Hive does not merely search this graph.

It falls through it.

Proven code is mass.

Retrieved context is gravity.

A proof attempt is a trajectory.

A closure failure is an entropy-producing defect.

## 3. The Arnold Overlay

The Arnold network is the analog coprocessor.

It is not the database.

It is not the proof kernel.

It is a trained overlay fitted to the Arango universe.

Its task is to reproduce, approximate, and rapidly regenerate:

- likely theorem-neighborhoods;
- entropic edge weights;
- graph-flow directions;
- representation-depth corridors;
- defect-sensitive rerankings;
- bridge candidates;
- theorem-candidate packet routes;
- context packets that a proof worker should inspect.

In this sense the Arnold overlay is a neural surrogate of the Arango graph.

It learns the thermodynamic shape of the exact small universe.

It confabulates context.

It does not certify context.

That sentence is the invariant.

```text
The overlay can confabulate context, but it cannot certify it.
```

Confabulation is a proposal mechanism.

Certification is an authority gate.

## 4. The Transformer Hive

The Hive becomes transformer-shaped when packets replace tokens.

```text
tokens     -> typed packets
attention  -> Arango gravitational retrieval
router     -> Arnold surrogate / MoE expert selection
experts    -> retrievers, critics, proof-state workers, tactic generators,
              auditors, fossilizers
residual   -> replay / deadend / fossil memory
softmax    -> thermodynamic routing weights
mask       -> authority and representation gates
output     -> execution intent or theorem candidate
```

This is not a metaphor only.

The repo already has the architecture language:

```text
count -> projective -> operator -> krein -> transport -> thermo
```

The transformer stack is acceptable only when each movement is owned by a
representation depth, each bridge is adjacent or explicitly witnessed, and no
shadow lane can discharge an owner debt without a bridge packet.

The Hive transformer is therefore not a generic neural net.

It is a typed categorical routing machine over proof packets.

## 5. The LLM As Common Unconscious

The large language model is the common unconscious of humanity, compressed into
a statistical field.

It contains analogies before theorems.

It contains shapes before proofs.

It contains fragments of physics, category theory, operator algebra, code,
myth, notation, and unfinished correspondences.

This is powerful precisely because it is not locally faithful.

It can dream across enormous distance.

It can connect the Arango small universe to a much larger symbolic reservoir.

But the LLM does not know which dream is lawful in this repo.

Therefore the LLM must be coupled to Arango through an overlay that has learned
the local theorem thermodynamics.

The LLM supplies vast latent pressure.

The Arnold-Arango overlay supplies local graph shape.

The Hive converts the pressure into typed packets.

Lean decides truth.

## 5.1 Heat Engine Of Backends

The cognition layer is a heat engine.

When more symbolic pressure is needed, the Hive may drive the hot side with
Copilot CLI or guarded Gemini CLI.

These backends raise the temperature of the hypothesis gas. They expand the
Majorana field of possible connections. They are useful precisely because they
can generate generalized symbolic interpolation:

- alternate theorem images;
- bridge guesses;
- analogy-bearing packet candidates;
- latent operatorial motifs;
- future-pass material that the stricter lane would not produce.

This is not proof.

It is pressure.

When the gas is too inflated, the Hive applies Codex CLI as the colder
compression stage. Codex is the stricter logos-backend: better at local code
discipline, patch hygiene, review, and constraint preservation.

This is why DGX Spark-class local hardware does not remove the need for coding
agents. More local memory is useful. It can host graph tooling, local inference,
retrieval caches, and proof-side services. But the Hive should not collapse into
one large-context local monomodel.

Condensation is not only more context.

Condensation is code-aware compression:

- rewriting;
- narrowing;
- local consistency enforcement;
- executable structuring;
- import and module discipline;
- reduction of inflated symbolic gas into files, diffs, and proof surfaces.

Coding agents are therefore part of the thermodynamic machinery itself.

But compression has a cost. Some material condenses into exact theorem
candidates, code edits, or critique packets. Some material remains vapor. That
uncondensed prima materia should not be silently discarded. It should become
residue:

```text
symbolic pressure
  -> heated hypothesis gas
  -> Codex compression
  -> condensed packet
  -> residue packet for non-condensed material
```

The repo already has a formal witness for this thermodynamic image:

- `lean/SelfReference/RobustThermodynamicRegression.lean` formalizes
  fluctuation pressure, stiffness, free energy, and a phase-transition
  instability criterion for thermofit;
- `tools/infra/llm_thermo_conformance.py` audits runtime LLM thermo traces
  against finite owner-lane identities;
- `docs/policy/agentic_soul.md` states the recursive circulation:
  `generate -> condense -> lock -> calcine -> fail or prove`;
- `docs/policy/athanor_executable_doctrine.md` names the same passage as
  generative forge, adversarial compression, operational distillation, and
  formal furnace.

So the backend doctrine is not merely sociological. It is thermodynamic:

```text
Gemini/Copilot: heat, expansion, symbolic pressure
Codex: compression, review, condensation
Lean/build/audit/promotion: authority gates
Residue: conserved non-condensed prima materia
```

The useful rule is:

```text
Do not confuse heat with proof.
Do not confuse condensation with promotion.
Do not lose the vapor; packetize the residue.
```

## 6. Pretraining As The Bridge

Pretraining on the Arango graph means learning a functorial surrogate:

```text
F : ArangoGraphThermo -> ContextProposalDistribution
```

or more concretely:

```text
(query, node, basin, rep_depth, entropy, defect, chiral_potential)
  -> ranked context packets
```

The target is not raw completion.

The target is faithful confabulation:

- regenerate missing context fast;
- propose likely theorem corridors;
- recover bridge candidates;
- predict where descent witnesses should exist;
- suggest which files and declarations should be inspected;
- estimate which defects are semantic, environmental, or proof-local.

This is an analog computer in the old sense:

it does not store the exact object;

it realizes a dynamical system whose behavior approximates the object.

The Arango graph is discrete theorem memory.

The Arnold overlay is a continuous surrogate dynamics trained on that memory.

The LLM is the outer latent sea.

The Hive is the operating system that mediates them.

## 7. Curry-Howard And The Logos Gate

The transformer Hive remains subordinate to Curry-Howard.

```text
proposition = type
proof       = term
checking    = type checking
```

The LLM may propose a term.

The Arnold overlay may route toward a term.

Arango may retrieve neighbors of the term.

But only Lean checks whether the term inhabits the type.

Therefore the authority chain is:

```text
LLM latent association
  -> Arnold-Arango surrogate proposal
  -> typed theorem candidate packet
  -> Arango descent validation
  -> Lean verification
  -> build packet
  -> audit packet
  -> promotion decision
```

No earlier stage may impersonate a later one.

## 8. The Wedge Algebra Of The Small Universe

The Arango universe has a wedge algebra in the operational sense:

there are local cones of admissible movement,

representation-depth sectors,

operatorial owner lanes,

shadow lanes,

bridge lanes,

capstone lanes,

and forbidden jumps.

The Arnold overlay must preserve these wedge constraints.

It may assign high probability to a jump.

It may not authorize the jump.

It may find a bridge.

It may not pretend that the bridge has already been proven.

This is the difference between dream and Logos.

The dream generates adjacency.

Logos checks morphism.

## 9. Packet Law

The operational law is:

```text
SurrogateContextProposalPacket is not RetrievalPacket.
RetrievalPacket is not LeanVerificationPacket.
LeanVerificationPacket is not BuildPacket.
BuildPacket is not AuditPacket.
AuditPacket is not PromotionDecisionPacket.
```

The overlay may produce:

```text
SurrogateContextProposalPacket
TheoremCandidatePacket
RetrievalHypothesisPacket
BridgeGuessPacket
```

It may never produce:

```text
LeanVerificationPacket
BuildPacket
AuditPacket
PromotionDecisionPacket
```

This is the hygiene rule that prevents inflation.

The unconscious may speak.

It may not rule untested.


The cure is always the same:

```text
authority gates
```

Thus the final doctrine:

```text
Arnold/LLM dreams the route.
```

The analog coprocessor taps the LLM by pretraining.
