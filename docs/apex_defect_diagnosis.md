This note records the current doctrine for local structural diagnostics over the
repository DAG.

It is a diagnostic note only. It does not rank theorem truth, depth, or
scientific value.

## Current purpose

The useful question is not “which theorem is important?” but:

- where does a local causal neighborhood fail to factor cleanly,
- where is support artificially compressed,
- where are comparison theorems missing, and
- where does architectural flow rely on wrappers instead of adjacent bridges.

That remains the right use of apex-local diagnostics.

## Current defect vocabulary

The defect profile remains centered on:

- shell thinness
- support collapse
- witness imbalance
- facade mediation
- unsound support
- skip-layer clustering
- boundary fragility
- replacement fragility

These should be read as local structural diagnostics, not as summary scores.

## Current repository use

Right now this framework is most relevant for checking:

- whether the corrected phase-space trunk is actually feeding the polarized and
  recomposition junctions;
- whether the Weyl branch is still scalar-attached rather than operator-fed;
- whether count/projective has a real meeting theorem with the main trunk at
  polarization; and
- whether compatibility scaffolds are still acting like hidden roots.

## Output doctrine

The correct output is still a dossier, not one scalar:

- carrier scope
- raw metrics
- severity vector
- bottleneck witness set
- thin transitions
- witness deficits
- facade mediation
- unsound support
- skip-layer inventory
- boundary fragility
- repair candidates
- source paths

The raw block remains primary. Any discretized severity is only a convenience.

## Validation standard

Keep this framework only if it helps separate:

- semantic roots from old hubs;
- genuine coherence files from wrapper accumulators; and
- real branch junction debt from harmless packaging.

If it collapses back into centrality scoring, it is not useful.
